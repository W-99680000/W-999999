# live-subtitle　外文视频实时翻译字幕

看外文视频，**既没字幕也没翻译**时，给你实时中文字幕。

**双层显示**：置顶浮窗（译文为主 + 原文为辅 + 保留最近 5 条）＋ 同步写 `.srt`（播放器可加载）。

---

## 快速开始

```
双击  start.bat        分块模式（默认，字幕与音频同步）
双击  stream.bat       流式模式（首字更快，见下）
```

启动后**去播放你的视频**，字幕自动出现。关掉控制台即停止。

```bat
python live_subtitle_v2.py --from ja --to zh     # 换语言
python live_subtitle_v2.py --selftest            # 自检（39 项）
python overlay_qt.py --selftest                  # 浮窗自检（25 项）
python overlay_qt.py --demo                      # 只测浮窗
```

## 显示规范（照搬成熟方案，不是我设计的）

浮窗的数值**取自成熟项目的默认配置**——
[VoxGo](https://github.com/zxbb1190/VoxGo_game_voice_trans)（GPL-3.0，同为
WASAPI 环回 + faster-whisper + 透明浮窗），来源是它的 `OverlayConfig`：

| 项目 | 值 | 理由 |
|---|---|---|
| `font_size` | **16** | 字幕字号要小；我原来用 26，太大 |
| `max_lines` | **5** | 保留最近 5 条，可回看 |
| `hold_seconds` | **5** | 每条停留 5 秒后淡出 |
| `text_color` | **#00FF00** | **译文是主角**（大、亮） |
| `original_text_color` | **#B7C4D8** | **原文是配角**（小、暗） |
| `show_original` | True | 原文仍显示，供对照 |
| `bg_color` | #20242A | 深色底 |
| `opacity` | 0.92 | 成熟方案 0.85；实测叠视频上偏透，抬高一点 |

**核心设计：译文在前、原文退后。** 看视频的人需要的是译文，原文只是辅助核对——
这个主次关系决定了字号、颜色、位置。

**另加两项字幕常规做法：**
- **文字描边**（`-webkit-text-stroke`）：浅色画面上亮字会糊在背景里，描边保证任何背景都能读
- **主题切换（T 键）**：暗画面用亮绿字；亮画面用白字+重描边

## 翻译规范（同样照搬）

VoxGo 的 `SYSTEM_PROMPT` 里这几条，是实时字幕翻译该有的纪律：

```
· 只做忠实翻译，不补全没听到的内容
· 不要扩写，不要解释，不要润色成完整句
· 如果原文明显不完整，保留不完整感
· 某个词无法确定，用"（听不清）"或保留原词
· 术语、人名、品牌名、缩写优先保留原文
```

本程序在这基础上做了三件事：
1. **短句表**（72 条口语高频）：`What?` → `什么？`，零延迟且不会错
2. **会话缓存**：重复台词直接复用，保证一致
3. **胡话识别**：argos 偶尔吐文言垃圾
   （实测：`She'll hate me forever...` → `亦复如是. 师曰. 那她会永远恨我`）
   → 检出「亦复如是 / 师曰 / 子曰」等，以及长度严重失衡的译文，**不给它进缓存**

**长句会退化，所以默认单段压到 4 秒**（`--max-seg 4.0`）。
实测依据：`If my mother disagrees with something...` → `…我们等着瞧吧`（尾句乱造）。
成熟方案 VoxGo 的 `max_speech_seconds` 均衡档也是 4.5。

## 性能（实测，非估算）

### 延迟构成：固定开销才是瓶颈

```
bench_latency.py：
  **耗时 = 0.04×音频秒 + 1.08s**
  0.5s 音频 → 1.11s (0.45×)
  8.0s 音频 → 1.42s (5.65×)
```

**固定开销 1.08 秒是绝对瓶颈，可变成本只有 0.04 秒/秒。**
由此**推翻三个想当然的方案**：关 VAD（1.54s，反而更慢）、降 beam（1.29s）、换小模型
（不动那 1.08 秒），**全都没用**。

### 两套模式：这是实测出来的取舍，不是"哪个更好"

参照 [Macháček et al. 2023 "Turning Whisper into Real-Time Transcription System"](https://aclanthology.org/2023.ijcnlp-demo.3.pdf)
（Whisper-Streaming，CUNI）的 **LocalAgreement-2** 策略实现流式模式：

| | 分块模式（默认） | 流式模式 `--stream` |
|---|---|---|
| 原理 | 攒够一段音频再转写 | LocalAgreement-2：重跑缓冲，取两次输出的**最长公共前缀**作为"稳定"部分 |
| **首字延迟** | 段长 + 1.5s ≈ **5.5s** | **≈ 0.5–2s**（一次更新耗时） |
| 字幕与音频同步 | ✅ 不积压 | ⚠️ 长时间连续说话会积压 |
| 缓冲 | 无 | 锯齿形，上限 10s（可调） |
| 适用 | 一般观看 | 对话密集、想尽快看到字 |

### 流式模式的实测数据

```
bench_localagree.py：每次更新耗时几乎恒定，与缓冲长短几乎无关
    缓冲 0.5s → 1.46s      缓冲 8.0s → 1.61s
    缓冲 2.0s → 1.38s      缓冲 12.0s → 1.80s

bench_trend.py（60–90 秒长跑，每 2 秒采样缓冲深度）：
    base / 8线程 / 间隔0.5s → 均耗 0.49s，更新 45 次
    缓冲深度：8 4 4 3 4 →12 11 11 11 10 10
  → **前 10 秒缓冲只有 3–4 秒（字幕几乎实时）；
     之后爬到 10–12 秒卡住 —— 因为 0.49s × 2 次/秒 ≈ 0.98 音频秒/秒，
     刚好卡在追平 1.0 的临界点上。**
```

**这个约束是硬件决定的，不是实现问题。** 论文能达到 3.3 秒延迟，是因为它跑在
**NVIDIA A40 GPU（RTF≈0.1）**；本机无 GPU（cuBLAS 缺失，实测），只能吃这个约束。
所以本实现**不假装能追平实时**，而是把"追不上"的后果**限制在一个固定的缓冲上限内**。

### 模型选型（bench_fastest.py）

```
tiny  / int8 / 8线程 → 4秒音频 0.19s → 20.75× 实时
base  / int8 / 8线程 → 0.37s         → 10.86×
small / int8 / 4线程 → 1.25s         →  3.21×
```

**注意：这些数字有误导性。** 真正决定能力的是
**「每次更新的固定开销 ÷ 更新间隔」**，不是单次 RTF。
流式模式默认用 `base`（比 small 快 3 倍），就是为了压低这个比值。

### 其它

```
翻译：argos 离线，平均 0.04 秒/句（占实时预算 1%）
分块模式端到端：处理 2.4–4.4× 实时，延迟 1–2 秒（指处理时间，不含攒段）
```

## 语言支持（**这里要说实话**）

### 识别：whisper 支持 99 种语言，但**不能强制错语言**

**这一条是用户实际踩到的坑**：看越南新闻时字幕全是错的。原因是代码默认强制 `lang="en"`。

实测（`test_vietnamese.py`，真实越南新闻音频）：

```
① 自动检测：检出 vi，置信度 0.976  → 识别正确
   "Sẵn hùng sau, Xung mang xe đạp đi bán, rồi mua tàu về quê."
② 强制 en（这就是出错的原因）：
   "In the next episode, Xung Mang will go to the market and buy a boat..."
   ↑ **whisper 不是"听错"，是把越南语直接意译成英文，而且译错**
```

→ 所以现在**默认自动检测**（`--lang` 可固定；`--no-detect` 关掉检测）。

### 翻译：不同语言对的可用程度差别很大（实测）

| 语言对 | 路径 | 速度 | 质量 |
|---|---|---|---|
| **en → zh** | argos 直连 | 0.04s/句 | 好（离线） |
| **ja → zh** | 无中继，走在线 | ~1s | 差 |
| **vi → zh** | argos 中继 vi→en→zh | ~0.2–0.5s/句 | **糙**（见下） |

**越南语的质量必须讲清楚**——实测问题：

```
VI: máu lạnh（冷血）      → ZH: 凉血          应译"冷血"
VI: Dũng（人名）          → ZH: 艾瑞克 / 埃里克   人名丢失
VI: Gió trung dũng đến…   → ZH: 忠心的风来…     人名被当普通词
```

**argos 没有 `vi→zh` 直连包，只能中继，而中继会二次损失。** 测过的替代方案：

| 方案 | 结果 |
|---|---|
| **MyMemory 在线直译** | **废弃**。实测返回的是维基百科模板而非译文：<br>`(原始内容存档于2019-09-29). Vå 2 Uông Bí…`、`ã(学名:…)为ệ科ệ属下的`、`请检查date中的日期值 (帮助)` |
| **whisper `task=translate` + en→zh** | **废弃**。3–9 秒/段（慢于实时），且 en→zh 会输出文言文：<br>`定稻田无鬼。故食米饭。`、`必有能行者,唯一人能行.` |
| **argos 中继**（当前采用） | 唯一能跑进实时的，0.2–0.5s/段。质量糙但**是在翻译** |

> **顺带解开一个旧谜团**：之前看到的"亦复如是 / 师曰"这类文言垃圾，
> 来源就是 argos 的 en→zh 模型（它在英文输入不稳时会滑向文言）。
> 现在 `_looks_broken()` 会拦住这类输出。

**结论：越南语现在是"能看个大概"，不是"能看准确"。要准确需要专门的 vi→zh 模型（本机没有）。**

### 噪声过滤（都是实测踩出来的）

| 滤除对象 | 实测例子 | 判据 |
|---|---|---|
| 泰文/老挝文 | `แล ้ ว เจ ็ บ เจ ้ า` | Unicode 区间 |
| **ASS 字幕样式代码** | `fn黑体fs22bord1shad03aHBE4aH00fscx67fscy662cHFFFFFF3cH` | 已知标签 ≥3 个，或"字母+数字"连续 3 组 |
| 维基模板 | `(原始内容存档于2019-09-29)`、`(学名:…)为科属下的`、`请检查date中的日期值 (帮助)` | 关键字 + "多个短片段无实词" |
| 变音残片 | `ườ ườ ạ ạ` | 多个短片段且无一个长度 ≥3 |
| **但不能误杀** | `谢谢`、`好`、`是`、`Cảm ơn các bạn` | 单短词合法 → 必须放行 |

## 三个必须知道的限制

**1　必须走默认输出设备。** 播放器把音频指到 HDMI/蓝牙，字幕窗就一直空白。

**2　没播放 = 没字幕，这不是故障。**
WASAPI 环回只在系统音频引擎真在出声时才回传数据。
（实测：不播放时 20 秒 0 回调；一播放每秒 96,256 样本。）

**3　翻译模型按语言对装。** 本机有 `en→zh`、`en→ja`、`en→fr`；**没有 `ja→zh`**（argos 索引里就没有）。

## 踩过的坑（都写进代码注释了）

| 坑 | 现象 | 解法 |
|---|---|---|
| **tkinter 浮窗不可见** | 系统层面全正常（IsWindowVisible、TOPMOST、DWM cloaked=0、像素里也有文字），用户就是看不到。试过 overrideredirect / Win32 强制置顶 / WS_POPUP / 纯 Win32 原生窗口，全失败 | **换 PyQt5**：`Qt.Tool + WA_TranslucentBackground` |
| **Qt 换完仍不渲染** | 接进主程序后浮窗不出现 | **GUI 操作必须主线程**：工作线程丢队列，主线程 QTimer 取 |
| **`.bat` 中文被拆断** | cmd.exe 按 GBK 读 `.bat`，中文变乱码把命令拆开 | 启动器一律纯 ASCII |
| **设置文件自我循环** | 程序算出的坐标存回设置文件，下次读回来，坏值永远出不去 | 载入时校验，越界值丢弃 |
| **坐标系混用** | 物理 1920x1080 / 缩放 125%，Tk 报 864 而 Win32 报 1020 | 统一用 `SystemParametersInfo(SPI_GETWORKAREA)` |
| **`huggingface.co` 不通** | argos 取分词模型时 ConnectTimeout | 初始化时强制预热 + 失败降级；模型从 `argos-net.com` 直链下 |
